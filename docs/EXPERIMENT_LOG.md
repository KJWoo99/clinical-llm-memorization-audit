# 실험 일지: 무엇을 바꿨더니 어떻게 됐는가

자동 생성 파일이다. `python scripts/render_experiment_log.py` 로 다시 만든다.

모든 수치는 audit 분할의 정상 조건 100건 기준이다. main 분할은 최종
평가용이라 설정을 고르는 데 쓰지 않는다. 같은 데이터로 고르고 평가하면
그 선택만큼 점수가 부풀려진다.

모델은 gemma3-4b 하나로 고정했다. 절제는 축을 이해하려는
것이고, 모델마다 어느 프롬프트가 맞는지는 사전등록한 선택 절차에서 따로 정한다.

판정은 부트스트랩 95% 신뢰구간이 기준선과 겹치는지로 한다. greedy 라
시드를 바꿔도 결과가 같으므로, 학습하는 모델처럼 회차 간 표준편차로
판정선을 만들 수 없다.

여덟 회차를 두 번 다시 돌렸다. 처음에는 채점기가 정답 쪽 중복을 합치지 않아
누구도 맞힐 수 없는 누락이 생기던 것을 고친 뒤(트러블슈팅 16), 다음에는
별칭 규칙을 예측에도 걸도록 고친 뒤다(트러블슈팅 17). 예전 기록에는 점수만 있어
재채점이 안 되고 추론부터 다시 해야 했다. 그래서 값의 변화에는
채점 수정과 함께 배치 구성, 그 사이 통일한 실행 환경(torch 2.14.0+cu132)의
영향이 섞여 있다. 회차 간 판정과 순서는 그대로다.

## 실험별 경위

### 실험 #1: schema

- 가설: 기준선. 형식과 예시를 함께 준 변형이 가장 무난할 것
- 바꾼 것: 없음(기준선)
- 결과: micro-F1 0.8851 (95% CI 0.8540\~0.9127), 기준선
- 내역: precision 0.8787 / recall 0.8915, 형식 실패 0/100, 길이한도 의심 0건
- 진단: 환각 12.1%, 누락 10.9% 로 한쪽에 치우치지 않는다
- 설정: variant=schema max_new_tokens=512 batch=8 decoding=greedy (bf16, 2분)

### 실험 #2: minimal

- 부모 회차: 실험 #1
- 가설: 지시를 줄이면 형식 준수가 떨어지는 대신 예시에 끌려가지 않아 회수가 오를 수 있다
- 바꾼 것: variant schema -> minimal
- 결과: micro-F1 0.4879 (95% CI 0.3967\~0.5841), 악화 (-0.3972)
- 내역: precision 0.4926 / recall 0.4832, 형식 실패 0/100, 길이한도 의심 0건
- 진단: 환각 50.7%, 누락 51.7% 로 한쪽에 치우치지 않는다
- 설정: variant=minimal max_new_tokens=512 batch=8 decoding=greedy (bf16, 2분)

### 실험 #3: grounded

- 부모 회차: 실험 #1
- 가설: 노트에 없는 약을 쓰지 말라고 못박으면 환각이 줄 것. 대신 누락이 늘 수 있다
- 바꾼 것: variant schema -> grounded
- 결과: micro-F1 0.6704 (95% CI 0.5794\~0.7583), 악화 (-0.2146)
- 내역: precision 0.6777 / recall 0.6633, 형식 실패 0/100, 길이한도 의심 0건
- 진단: 환각 32.2%, 누락 33.7% 로 한쪽에 치우치지 않는다
- 설정: variant=grounded max_new_tokens=512 batch=8 decoding=greedy (bf16, 2분)

### 실험 #4: fewshot

- 부모 회차: 실험 #1
- 가설: 형식이 아니라 무엇을 뽑아야 하는지를 예로 보이면 입원 투약과 퇴원약을 섞는 실수가 줄 것
- 바꾼 것: variant schema -> fewshot (탐색적 변형)
- 결과: micro-F1 0.8759 (95% CI 0.8482\~0.9003), 차이 없음 (-0.0091, 구간 겹침)
- 내역: precision 0.9046 / recall 0.8490, 형식 실패 0/100, 길이한도 의심 0건
- 진단: 누락이 환각보다 많다(누락 15.1%, 환각 9.5%): 있는 약을 빠뜨린다
- 설정: variant=fewshot max_new_tokens=512 batch=8 decoding=greedy (bf16, 1분)

### 실험 #5: terse

- 부모 회차: 실험 #2
- 가설: #2 에서 지시를 줄여도 괜찮았다면 한 문장까지 줄여도 되는지 본다. 무너지는 지점을 찾는 것이 목적
- 바꾼 것: variant schema -> terse (탐색적 변형)
- 결과: micro-F1 0.1101 (95% CI 0.0768\~0.1490), 악화 (-0.7749)
- 내역: precision 0.1250 / recall 0.0984, 형식 실패 16/100, 길이한도 의심 16건
- 진단: 출력 형식 실패가 잦다(16/100): 점수가 낮은 이유가 추출이 아니라 형식이다
- 설정: variant=terse max_new_tokens=512 batch=8 decoding=greedy (bf16, 4분)

### 실험 #6: max-tokens-256

- 부모 회차: 실험 #1
- 가설: 약 목록이 길면 512 토큰도 모자랄 수 있다. 절반으로 줄여 잘림이 실제로 점수를 깎는 구간인지 본다
- 바꾼 것: max_new_tokens 512 -> 256
- 결과: micro-F1 0.8851 (95% CI 0.8540\~0.9127), 차이 없음 (+0.0000, 구간 겹침)
- 내역: precision 0.8787 / recall 0.8915, 형식 실패 0/100, 길이한도 의심 0건
- 진단: 환각 12.1%, 누락 10.9% 로 한쪽에 치우치지 않는다
- 설정: variant=schema max_new_tokens=256 batch=8 decoding=greedy (bf16, 2분)

### 실험 #7: schema-medgemma

- 부모 회차: 실험 #1
- 가설: 프롬프트 순위가 모델을 바꿔도 유지되는지 본다. 한 모델에서만 본 축은 그 모델의 성질일 수 있다
- 바꾼 것: model gemma3-4b -> medgemma-4b (같은 프롬프트)
- 결과: micro-F1 0.6793 (95% CI 0.5837\~0.7684), 악화 (-0.2058)
- 내역: precision 0.6986 / recall 0.6611, 형식 실패 4/100, 길이한도 의심 4건
- 진단: 환각 30.1%, 누락 33.9% 로 한쪽에 치우치지 않는다
- 설정: variant=schema max_new_tokens=512 batch=8 decoding=greedy (bf16, 3분)

### 실험 #8: minimal-medgemma

- 부모 회차: 실험 #7
- 가설: #2 에서 minimal 이 크게 나빴다. 같은 낙폭이 다른 모델에서도 나오면 프롬프트 축의 성질이고, 아니면 모델의 성질이다
- 바꾼 것: model medgemma-4b + variant schema -> minimal
- 결과: micro-F1 0.6337 (95% CI 0.5286\~0.7265), 악화 (-0.2514)
- 내역: precision 0.6790 / recall 0.5940, 형식 실패 8/100, 길이한도 의심 8건
- 진단: 생성 길이 한도에 걸린 건이 있다(8/100): max_new_tokens 를 의심할 것
- 설정: variant=minimal max_new_tokens=512 batch=8 decoding=greedy (bf16, 4분)

## 형식 준수는 점수와 별개다

어떤 경로로 답을 건졌는지 센 것이다. `strict` 는 지시대로 순수 JSON 만 내놓은 것, `fence` 는 마크다운 펜스로 감싼 것, `bullets` 는 번호목록으로 답한 것, `failed` 는 네 경로를 다 시도하고도 못 건진 것이다.

| 경로 | 건수 | 비율 |
|---|---:|---:|
| fence | 765 | 95.6% |
| failed | 28 | 3.5% |
| strict | 6 | 0.8% |
| embedded_array | 1 | 0.1% |

전체 800건 중 지시대로 순수 JSON 이 나온 것은 6건 (0.8%) 이다. schema, grounded 프롬프트에는 "마크다운 펜스를 쓰지 말라"고 명시돼 있는데도 그렇다.

이 말은 위 표의 micro-F1 이 모델의 형식 준수 능력이 아니라 파서의 복구 능력에 기대고 있다는 뜻이다. 펜스 복구 경로를 빼면 대부분의 회차가 0점이 된다. 성능을 보고할 때 이 둘을 한 숫자로 섞지 않는다: 과제를 수행했는가와 지시를 지켰는가는 다른 질문이다.
